# 开发文档

## 1. 项目定位

本项目是一个轻量级的员工信息管理 Web 应用，适合做内部管理工具、信息登记系统、员工资料查询系统等场景。

## 2. 架构概览

### 2.1 技术架构

- Web 层：Flask
- 数据层：SQLite
- 数据处理：pandas + openpyxl
- 搜索能力：拼音首字母辅助检索
- 身份认证：Session + Werkzeug 密码哈希

### 2.2 核心模块

- `app.py`：Flask 应用入口，只负责初始化、全局异常处理和路由注册
- `app_common.py`：统一响应、认证装饰器、员工字段清洗和 API 字段常量
- `auth_routes.py`：登录、登出和登录状态路由
- `page_routes.py`：页面路由
- `employee_routes.py`：员工和回收站 API
- `import_export_routes.py`：Excel 导入导出 API
- `admin_routes.py`：日志、备份和用户管理 API
- `config.py`：集中配置（环境变量可覆盖）
- `db.py`：数据库访问层（连接、建表、迁移、查询助手）
- `excel_utils.py`：Excel 导入导出共享逻辑
- `smart_import_service.py`：任意员工表字段识别、本地数据提取、分类和选择性写入
- `smart_fill_service.py`：工资表模板快照、AI/本地表头识别、安全写入和校验
- `log_utils.py`：日志模块（按天滚动落盘、日志查询/筛选/分页）
- `backup_utils.py`：SQLite 在线备份、完整性校验和旧备份清理
- `gzb_backup.py`：手动备份命令行入口
- `gzb_admin.py`：CLI 管理脚本
- `gzb_find.py`：查询脚本
- `gzb_update.py`：数据导入脚本
- `gzb_output.py`：结果生成脚本
- `templates/`：页面模板（index / login / admin / recycle_bin）

## 3. 数据模型

数据库文件：`sjk.db`

### employees 表

字段说明：

- `real_name`：姓名，主键
- `id_number`：身份证号
- `bank_account`：银行账号
- `bank_address`：银行地址
- `phone`：电话号码
- `sx`：姓名拼音首字母，用于搜索
- `deleted`：软删除标记，0 在职 / 1 已删除
- `deleted_at`：删除时间（审计）
- `deleted_by`：删除操作人（审计）

索引：`idx_employees_deleted_sx ON employees(deleted, sx)`。
旧库启动时自动迁移补列（幂等），无需手工处理。

### users 表

字段说明：

- `id`：自增主键
- `username`：用户名，唯一
- `password_hash`：哈希后的密码
- `is_admin`：是否为管理员
- `created_at`：创建时间

## 4. 核心接口说明

### 登录接口

- `POST /api/login`

参数：

```json
{
  "username": "admin",
  "password": "123456"
}
```

- `POST /api/logout`：清除登录状态
- `POST /api/change-password`：用户修改自己的密码（需登录，普通用户和管理员均可）
  - 参数：`old_password`（当前密码）、`new_password`（新密码，至少 4 位，规则与管理员重置密码一致）
  - 旧密码验证失败返回 400，用户已被删除返回 404
- 页面路由：`/change-password`（修改密码页面，需登录）

### 员工查询接口

- `GET /api/search?name=张三（搜索结果按姓名升序排列）`
- `GET /api/employees?page=1&page_size=20`：在职员工分页列表
  - `page`：页码，从 1 开始，默认 1
  - `page_size`：每页数量，默认 20，服务端上限 100
  - 返回：`data`、`total`、`page`、`page_size`、`pages`

### 员工新增/更新接口

- `POST /api/employee`
- `PUT /api/employee`

### 员工删除接口

- `DELETE /api/employee/<name>`（软删除，记录删除时间与操作人）

### 回收站接口

- `GET /api/recycle-bin?page=1&page_size=20`：已删除记录分页列表（按删除时间倒序）
  - `page`：页码，从 1 开始，默认 1
  - `page_size`：每页数量，默认 20，服务端上限 100
  - 返回：`data`、`total`、`page`、`page_size`、`pages`
- `POST /api/employee/<name>/restore`：恢复记录
- `DELETE /api/employee/<name>/permanent`：彻底删除（仅管理员，仅限回收站中的记录）

### Excel 上传导入接口

- `POST /api/import-preview`：multipart 上传 `.xlsx`（≤5MB，内存解析不落盘），返回逐行校验报告（new/update/restore/error + messages）与分类统计
- `POST /api/import-confirm`：接收确认的行数据，服务端重新清洗分类后单事务写入
- `POST /api/smart-import-preview`：multipart 上传任意表头的 `.xlsx` 员工表；模型只识别脱敏表头结构，服务端本地提取姓名、身份证号、银行账号、开户行和电话，返回字段映射、逐行数据及 new/update/restore/error 分类预览
- `POST /api/smart-import-confirm`：客户端再次提交同一文件、预览凭证及 `allow_new` / `allow_update` / `allow_restore` 控制项；服务端校验 SHA-256 指纹、重新解析并按确认时的数据库状态分类后，以单事务执行所选操作

解析/校验/写入逻辑统一在 `excel_utils.py`（`read_employee_excel` / `classify_import_rows` / `import_employee_rows`），Web 接口与 `gzb_update.py` 共用。

智能导入的预览凭证只保存文件指纹和经过验证的字段映射，不缓存源文件或数据行。确认更新或恢复时，只覆盖源表中已映射且非空的字段；源表缺少的列和空白值不会清空数据库已有信息。同一文件中的全部重复姓名均标记为错误，员工字段中的公式也禁止导入。新增、更新、恢复可以分别启用或关闭；确认阶段会重新分类，避免预览后数据库变化造成操作类型错误。

### Excel 导出接口

- `POST /api/export`：按 `input.xlsx` 姓名列表导出
- `POST /api/export-manual`：按请求 JSON 中的 `names` 列表导出
- `POST /api/smart-fill-preview`：multipart 上传 `.xlsx` 模板，可选 `names` JSON 数组；只识别并严格校验字段映射，返回工作表、目标列、原表头和置信度，以及 10 分钟有效的预览凭证，不写入模板
- `POST /api/smart-fill-confirm`：客户端再次 multipart 提交预览凭证和 `.xlsx` 模板；服务端核对文件 SHA-256 指纹后，使用已验证映射执行填写并返回文件。服务端不缓存模板文件，且客户端不能在确认阶段替换文件或篡改映射
- `POST /api/smart-fill`：保留为兼容入口，但拒绝直接填写，防止绕过映射预览确认
- 基础导出接口均在内存中生成 Excel 并以附件形式直接返回（`导出信息_时间戳.xlsx`），不写共享文件，多用户并发导出互不影响；智能填表同样全程在内存中处理并返回 `原文件名_已填.xlsx`
- AI 助手导出（`agent_tools.export_employees_tool`）在内存中生成 Excel，按随机 token 暂存于内存（上限 20 份、10 分钟过期，超限淘汰最早一份），不落盘
- `GET /api/chat/download/<token>`：凭 token 领取 AI 导出文件，以附件形式返回（文件名 `导出信息_时间戳_随机后缀.xlsx`）；前端聊天组件收到 `downloads` 字段后自动触发浏览器下载，并在气泡内保留下载按钮
- `export_employees_tool` 支持可选 `payroll` 参数（AI 从对话中提取的 `[{"name", "days", "daily_wage", "total_wage"}]`）：提供时在末尾追加"考勤天数/每日工资/总工资"三列。各列只填对话明确说出的数字；总工资未说但天数和日工资齐全时按 每日工资 × 考勤天数 计算（`excel_utils.build_export_buffer`），只有总工资时每日工资留空不反推；不传 payroll 时保持原 5 列不变
- 命令行脚本 `gzb_output.py` 仍写 `data/output.xlsx`（`GZD_OUTPUT_XLSX` 可覆盖）

智能填表复用 `GZD_AGENT_API_KEY`、`GZD_AGENT_MODEL` 和 `GZD_AGENT_BASE_URL`。模型只接收匿名工作表编号、合并区域、白名单表头候选和不含原值的行结构统计；真实工作表名称、数据行内容和数据库记录都不会发送。模型输出只作为字段映射方案，服务端会在本地还原工作表编号，并校验工作表、行号、列号、允许字段和置信度；每个目标列还必须在表头附近找到与数据库字段完全对应的白名单表头证据，否则整张映射不通过。通过校验的映射先展示给用户确认，确认后才由 `openpyxl` 本地写入。

写入阶段只使用所有目标字段均为空的完整空白行，并在“合计/总计/小计/汇总”等行之前停止，避免把新姓名拼接到半填写记录或汇总区域。新增行会复制模板数据行的样式和公式，公式引用按目标行平移；输出文件设置为打开和保存时完整重算。数据库文本强制按字符串写入，不能被 Excel 解释为公式。已有人工值和公式不会被覆盖。一次最多处理 5000 个姓名，XLSX 解压后总量限制为 100MB；模型超时、输出无效或调用失败时，只对常见中文表头启用经过同一套严格校验的本地规则回退。

### 操作日志接口

- `GET /api/logs`（仅管理员）
- 参数：`category`（`system` 系统日志 / `db` 数据库改动日志，默认 system）、`date`（YYYY-MM-DD，默认今天）、`level`、`keyword`、`page`、`page_size`（默认 50，上限 200）
- 返回：`logs`（倒序，最新在前）、`total`/`pages`、`stats`（各级别数量）、`dates`（可用日期列表）

日志分两类，各自独立文件、按天滚动（保留 30 天）：

- **系统日志** `logs/system.log`：登录/登出、导出/下载、HTTP 请求（werkzeug）、服务异常
- **数据库改动日志** `logs/database.log`：员工增删改/恢复/彻底删除、Excel 导入写入、用户管理

`log_utils.py` 提供 `sys_log` / `db_log` 两个 logger（打点按类别选用），行格式为 `时间 | 级别 | 模块 | 消息`，查询时按行解析，traceback 续行并入上一条消息。旧版单一日志 `app.log` 自动归入系统日志类别可读。日志目录可用 `GZD_LOG_DIR` 环境变量覆盖。

## 4. API 响应与状态码约定

所有 JSON API 都通过 `app_common.py` 中的 `api_ok()` 或 `api_err()` 返回，响应主体统一包含：

- 成功：`success: true`、`message`，以及接口数据字段
- 失败：`success: false`、`message`，以及可选的错误辅助字段

HTTP 状态码与业务含义保持一致：

- `200`：请求成功
- `400`：请求参数或业务校验失败
- `401`：未登录或登录凭据无效
- `403`：已登录但没有管理员权限
- `404`：接口或业务资源不存在
- `409`：资源状态冲突，例如用户名已存在或删除当前账号
- `413`：上传文件超过 5MB
- `500`：服务端异常，详细信息写入系统日志

前端仍可使用 `success` 字段判断业务结果；调用方应同时检查 HTTP 状态码，以便区分认证、校验、资源和服务端错误。

## 5. 关键实现点

### 5.1 登录与权限控制

项目通过装饰器实现：

- `login_required`
- `admin_required`

登录态使用 Flask 的 `session` 实现。

### 5.2 拼音首字母

通过 `pypinyin` 计算姓名的首字母，用于支持拼音搜索：

```python
lazy_pinyin(name, style=Style.FIRST_LETTER)
```

搜索接口对关键词中的 `%`、`_` 使用 `ESCAPE '\'` 转义，按字面匹配。

### 5.3 数据库访问

统一走 `db.py`：`query_all` / `query_one` / `query_paginated` / `execute` 助手自动管理连接；
`db_session(commit=True)` 上下文管理器用于多语句事务；`init_db()` 负责建表、索引与旧库幂等迁移。

### 5.4 软删除与回收站

员工删除为软删除（`deleted=1`），所有查询出口统一过滤 `deleted=0`；
员工列表和回收站均通过 `query_paginated` 分页查询，默认每页 20 条，服务端上限 100 条。
回收站页面 `/recycle-bin` 支持恢复（清除标记）与彻底删除（物理删除，仅管理员）。

### 5.5 数据库备份

`backup_utils.py` 使用 `sqlite3.Connection.backup()` 创建一致性备份，不直接复制正在使用的数据库文件。备份先写入临时文件，再执行 `PRAGMA integrity_check`，校验通过后使用原子替换生成正式备份文件。

系统默认不启动自动备份调度器。管理员通过 `/admin` 页面中的备份组件手动触发 `/api/admin/backup`，备份列表位于 `/backup`，下载接口为 `/api/admin/backup/<filename>`。`cleanup_backups()` 按 `GZD_BACKUP_RETENTION` 保留最新备份，默认保留 10 个文件；备份相关页面和接口均由 `admin_required` 保护。
